# Project Guide — Soil & Structure (start here)

This is the **single "start here" document** for continuing work on the Soil &
Structure website. If you copy this folder to another computer, follow
[Set up on a new computer](#1-set-up-on-a-new-computer) and you'll be running and
editing again in a few minutes.

> For the deployment / backend details, see **[README.md](./README.md)** (it has
> the full Backend Integration Guide). This guide focuses on **running and
> editing** the site.

---

## 1. Set up on a new computer

### Prerequisites
- **Node.js 18.18+ or 20+** (built and tested on Node 24). Download: https://nodejs.org
- **npm** (ships with Node). Any code editor (VS Code recommended).

### Steps
```bash
# 1. Open a terminal in the project folder (the one containing package.json)

# 2. Install dependencies (creates node_modules/)
npm install

# 3. Make sure the local env file exists.
#    If .env.local did not come across (e.g. you used git, which ignores it):
cp .env.example .env.local        # Windows PowerShell: Copy-Item .env.example .env.local

# 4. Start the dev server
npm run dev
#    → open http://localhost:3000
```

That's it. Edit a file, save, and the browser hot-reloads.

### What you do NOT need to copy between computers
These are regenerated by `npm install` / `npm run dev` and can be safely deleted
or left behind:
- `node_modules/`  → recreated by `npm install`
- `.next/`         → build cache, recreated automatically

### What you MUST have
- All source folders: `app/`, `components/`, `lib/`, `data/`, `types/`,
  `styles/`, `public/`
- Config files: `package.json`, `package-lock.json`, `tsconfig.json`,
  `tailwind.config.ts`, `postcss.config.mjs`, `next.config.mjs`
- `.env.local` (or recreate it from `.env.example`)

## 2. Everyday commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the dev server at http://localhost:3000 (hot reload) |
| `npm run build` | Production build — also type-checks and lints. Run before deploying. |
| `npm run start` | Serve the production build (run `build` first) |
| `npm run lint` | ESLint |
| `npm run typecheck` | TypeScript check with no output (`tsc --noEmit`) |

**Golden rule before finishing a session:** run `npm run build`. If it passes,
the site is healthy.

## 4. How to edit CONTENT (text, images, listings)

**All visible content is mock data in `/data/*.json`.** Components never hardcode
content — they read it through async functions in `/lib/data/`. To change words,
images, projects, services, etc., **edit the JSON in `/data/`.**

| To change… | Edit this file |
| --- | --- |
| Projects (case studies) | `data/projects.json` |
| Services | `data/services.json` |
| Testimonials | `data/testimonials.json` |
| Team / leadership | `data/team.json` |
| Job openings | `data/jobs.json` |
| Insights / articles | `data/insights.json` |
| Hero stats (25+, 400+…) | `data/stats.json` |
| Value-approach steps | `data/process.json` |
| Nav links, footer links, address, phone, email, socials | `data/site.json` |

**Adding an image:** drop the file into `public/images/…`, then reference it in
the JSON as `"/images/your-file.jpg"`. Always include a meaningful `alt`.

**Section headings / paragraphs that aren't in the JSON** (e.g. "Solid ground.
Sound structures.", "Ground up. Start to finish.") live directly inside the
matching component in `components/sections/`. Search the text and edit it there.

> Note: the data functions currently read local JSON. When the real
> Node.js + MongoDB API is built, only `/lib/data/*` changes — see the Backend
> Integration Guide in [README.md](./README.md).

## 5. How to edit the DESIGN (colours, fonts, spacing, radius)

Design tokens are centralised in **`tailwind.config.ts`**. Change them there and
every component updates. Components use token names (e.g. `bg-bone`, `text-ink`,
`bg-lime`) — never raw hex.

| Want to change… | Where |
| --- | --- |
| Brand colours (bone, ink, lime, muted, line) | `tailwind.config.ts` → `theme.extend.colors` |
| Fonts | `app/layout.tsx` (currently **Archivo** headings, **Instrument Sans** body). Swap the `next/font` imports; they feed the `heading`/`body` tokens. |
| Type sizes (display-sm/md/lg/xl, eyebrow) | `tailwind.config.ts` → `fontSize` |
| Spacing / section padding | `tailwind.config.ts` → `spacing`, or the `Section` component |
| Corner radius (pill, card, image) | `tailwind.config.ts` → `borderRadius` |
| Content width (1200 laptop / 1400 desktop) | `styles/globals.css` → `.container-page` + `maxWidth` tokens |
| Eyebrow label style + pulsing dot | `styles/globals.css` → `.eyebrow` |

### ⚠️ Important gotcha
**When you edit `tailwind.config.ts`, you must restart the dev server**
(`Ctrl+C`, then `npm run dev` again). Tailwind config is not hot-reloaded, and
you may briefly see a 500 error until you restart. Editing `.json`, `.tsx`, or
`globals.css` does NOT need a restart.

If port 3000 is stuck in use, either close the old terminal or start on another
port: `npm run dev -- -p 3001`.

## 6. Animations (what's been added and where)

All motion is dependency-free (CSS + IntersectionObserver) and automatically
disabled for users who prefer reduced motion (`motion-safe:` / `motion-reduce:`).

| Effect | Where it's defined / applied |
| --- | --- |
| Scroll reveal (fade + rise into view) | `components/ui/Reveal.tsx` — wrap any block in `<Reveal>` |
| Hero entrance stagger | `components/sections/Hero.tsx` (`animate-rise` + delays) |
| Count-up stats | `components/ui/StatItem.tsx` |
| Card hover lift + image zoom | `ServiceCard.tsx`, `ProjectCard.tsx` |
| Button hover lift / press / arrow | `components/ui/Button.tsx` (`withArrow` prop) |
| Nav link animated underline | `components/sections/Header.tsx` |
| Pulsing eyebrow dot | `styles/globals.css` `.eyebrow::before` + `animate-dot-pulse` |
| Pulsing hero CTA highlight | `Hero.tsx` (`animate-btn-pulse`) |
| Keyframes for all of the above | `tailwind.config.ts` → `keyframes` / `animation` |

To reuse the scroll reveal anywhere:
```tsx
import { Reveal } from "@/components/ui/Reveal";
<Reveal delay={100}>{/* your content */}</Reveal>
```

## 7. Customisations made beyond the original Figma
So a future editor knows what was intentional:
- **Full multi-page build** (Figma had one landing page). Interior pages match
  the landing system and are marked with code comments.
- **Fonts:** Archivo + Instrument Sans (chosen; the render looked serif).
- **Logo** sits on a white chip (5px padding, 10px radius) so it reads on the
  dark footer — `components/ui/Logo.tsx` and `components/sections/Footer.tsx`.
- **Container width:** 1200px up to large desktop, 1400px at ≥1440px.
- **Hero** rebuilt so the stats overlay inside the steel-frame photo (one panel).
- Added pulse animations, count-up, scroll reveals, hover polish, gradient depth
  on dark sections, balanced heading line-breaks.

## 9. Quick troubleshooting

| Symptom | Fix |
| --- | --- |
| `next: command not found` / module errors | Run `npm install` |
| Home page returns 500 after a style change | You edited `tailwind.config.ts` — restart `npm run dev` |
| "Port 3000 is in use" | Close the old dev terminal, or `npm run dev -- -p 3001` |
| Images 404 | Check the path starts with `/images/…` and the file exists in `public/images/…` |
| Env values missing | Ensure `.env.local` exists (copy from `.env.example`) |
| Styles look unstyled | Restart dev server; confirm `styles/globals.css` is imported in `app/layout.tsx` |
